# Rui 设计系统 — 基于 Compose Unstyled 的 KMP 中性 UI 实施计划

## 目标

在空仓库 `E:\Code\Native\Rui` 从零搭建：一个基于 Compose Unstyled（headless 原语库，v2.10.0，MIT）的独立设计系统库 **rui-ui** + 组件目录示例 App。

- **平台**：Android + iOS 必须（iOS 通过 CI/远程 Mac 验证）；架构保证未来加 `jvm`/`wasmJs` 目标即可支持桌面/Web（Unstyled 本身已发布这些目标），库代码不因此改动。
- **设计语言**：扁平中性基底 + 可选玻璃材质层——吸收 Material 的语义 token、状态层反馈、无障碍纪律；吸收 Liquid Glass 的半透明材质、以内容为中心的克制 chrome；不绑定任一平台视觉。
- **v1 范围**：主题系统 + Foundation + Button、IconButton、TextField、Switch、Checkbox、Dialog、Tabs。

## 技术选型（实现时取最新兼容的稳定 patch）

| 项 | 选择 |
|---|---|
| Kotlin | 2.4.x |
| Compose Multiplatform | 1.12.x |
| AGP | 9.x + `com.android.kotlin.multiplatform.library`（KMP-first 插件） |
| Gradle | 9.x（wrapper） |
| JDK | 17 |
| Unstyled | `com.composables:composeunstyled:2.10.0` |
| Android | minSdk 23 / compileSdk 36 |
| iOS 目标 | iosArm64 + iosSimulatorArm64（与 Unstyled 发布目标一致） |

关键约束：`gradle.properties` 设 `kotlin.native.ignoreDisabledTargets=true`，使 Windows 上 iOS 目标可配置但不编译；`rui-ui` **不依赖 material3**（仅 compose ui/foundation/runtime + composeunstyled），保证"中性"不泄漏 Material 视觉。

## 设计语言要点（写入 DESIGN.md）

1. **原则**：内容优先；中性表面 + 单一强调色；状态可感知；全平台统一几何语言；材质是增强而非依赖。
2. **RuiColorScheme**（明/暗两套，约 14 个语义角色）：`background / surface / surfaceElevated / outline / outlineSubtle / content / contentMuted / contentDisabled / primary / onPrimary / danger / success / scrim` 等。中性灰阶 + 单强调色，品牌色可整体替换。
3. **RuiTypography**：title/body/label 三层 × Lg/Md/Sm 九级，`FontFamily.Default`（Roboto/SF），后续可选捆绑 Inter。
4. **RuiShapes**：radius token（sm=8 / md=12 / lg=16 / xl=24 / full），组件按角色取用；squircle 连续圆角列为后续扩展点。
5. **RuiSpacing**：4dp 网格（4/8/12/16/24/32）；**RuiDimens**：触控目标 48dp、描边宽度等。
6. **状态层**（Material 优点）：pressed/hovered/dragged 用内容色 alpha 叠加（约 12%/8%），focused 用描边 focusRing 而非填充，提供统一 indication 实现。
7. **玻璃材质层**（Liquid Glass 优点）：`GlassSurface` 半透明 + `Modifier.blur`，平台能力探测（Android API 31+ / iOS Skia 实现，实现时验证），不支持时自动降级为 95% 不透明度的 surfaceElevated 纯色。v1 标记 `@ExperimentalRuiApi`。
8. **动效**：spring 预设（standard/fast/slow），overlay 类组件统一转场。

**主题 API**（Material 式人体工学，降低迁移成本）：

```kotlin
RuiTheme(darkTheme: Boolean = isSystemInDarkTheme(), colorScheme/typography/shapes 可注入) { … }
RuiTheme.colors / .typography / .shapes / .spacing
```

内部同时桥接 Unstyled theming（按其文档注册 `defaultMinimumComponentInteractiveSize` 等默认值），使未包装的原语也有合理行为。

## 组件模式（L2 统一范式）

每组件单文件、槽位化（leading/trailing/content）、默认值读 L1 token、所有视觉槽位可覆盖（默认好看，全部可换）：

```kotlin
@Composable
fun RuiButton(onClick, modifier, variant: Primary/Secondary/Ghost/Danger, size, enabled,
              shape: Shape = RuiTheme.shapes.md, colors = RuiButtonDefaults.colors(variant),
              leading, trailing, content) {
    UnstyledButton(  // 行为/键盘/Role 来自 Unstyled
        onClick, enabled,
        interactionSource = …,
        indication = ruiStateLayer()   // 我们的状态层
    ) { /* token 驱动的视觉 */ }
}
```

- **RuiTextField**：Unstyled Text Field 行为 + label/helper/error 布局与 token 样式
- **RuiDialog**：Unstyled Dialog（portal、Esc、paneTitle 无障碍）+ scrim + RuiSurface（可选玻璃背景）
- **RuiTabs**：Unstyled Tab Group（roving focus、键盘导航）+ 指示器样式
- **RuiSwitch / RuiCheckbox**：Unstyled 行为 + 中性轨道/勾选样式

## 示例目录 App

共享 `CatalogApp()`：组件分组导航（Foundation / Actions / Inputs / Overlay）+ 每组件 Demo 页（variant/size/参数开关）+ 全局明暗切换与玻璃降级开关。androidApp 单 Activity 挂载；iosApp 为 Xcode 工程（按 JetBrains 官方 KMP 模板结构手写 pbxproj）加载 framework 启动 `MainViewController`。

## CI（.github/workflows，push 到 GitHub 后生效）

- **android-ci.yml**（ubuntu）：`rui-ui` assemble + allTests + androidApp assemble
- **ios-ci.yml**（macos-15）：`rui-ui` iOS 目标编译 + iosApp `xcodebuild` 构建 + 模拟器启动截图上传 artifact

## 实施步骤

1. **脚手架**：git init + .gitignore；手写 Gradle 配置（catalog、wrapper、gradle.properties）；rui-ui 空 API 验证 Android 构建 + iOS 配置通过
2. **L1 主题**：token 全家桶 + RuiTheme + 明暗默认值 + Unstyled 桥接；commonTest 校验 token 完整性
3. **foundation**：RuiSurface / RuiIcon / RuiText / ruiStateLayer / GlassSurface（实验）+ 能力探测 expect/actual
4. **组件逐个实现**（顺序：Button+IconButton → TextField → Switch → Checkbox → Dialog → Tabs），每个组件落地同时在 sample 加 Demo 页
5. **sample androidApp** 本地跑通目录 App
6. **iosApp + ios-ci.yml**：Xcode 工程 + CI 工作流
7. **文档**：README（定位/快速开始/架构图）+ DESIGN.md（token 词典、新组件 checklist、换品牌色指南、未来加 desktop/web 的步骤清单）

## 验收标准

- Windows 本地：`gradlew :sample:androidApp:installDebug` 运行目录 App，明暗切换正常、全部 v1 组件可交互
- `gradlew :rui-ui:allTests` 通过；iOS 侧由 CI macOS runner 覆盖（编译 + xcodebuild 通过）
- 依赖审计：rui-ui 仅依赖 compose 基础 + composeunstyled，无 material3
- DESIGN.md 完整且"新增一个组件"的 checklist 可执行

## 风险与对策

- **iosApp pbxproj 手写**：无法本地验证 → 以官方 KMP 模板为底稿，CI 第一时间验证，必要时用 SPM 集成替代
- **CMP blur 平台差异**：能力探测 + 纯色降级是设计的一部分，不是补丁
- **Unstyled 迭代快（月 2-3 版）**：锁 2.10.0；其组件单文件哲学意味着必要时可 fork 进库
- **Kotlin/AGP/Gradle 版本矩阵演进快**：实现时查兼容矩阵取最新稳定组合再锁定
